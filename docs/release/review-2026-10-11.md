# Serlink Apple release review — 2026-10-11

## Source review and fix

The checkout started clean on `main` at `f6bf868`. Review found a native iOS
compile failure: the CloudKit bridge used macOS public SecTask entitlement APIs
that are absent from the iPhoneOS SDK. The iOS bridge now gates unsigned
simulator execution at compile time; device signing and CloudKit account/service
responses govern physical-device availability. macOS retains its entitlement
inspection. No remote vault/sync schema version changed.

Version 1.0.0 uses iOS build 12 and macOS build 16, independently of the Dart
package build suffix. Native fix and build numbers were committed and pushed as
`834161a`.

## Validation evidence

- Flutter 3.47.5 / Dart 3.13.4: analyzer has no issues. Full suite: 838 passed,
  15 skipped, zero failures. External SFTP fixtures and other opt-in smokes were
  skipped; this is not evidence for those external environments.
- Initial random VM-service/WebSocket upgrade failures were caused by local
  `LocalStack/1.0` HTTP discovery probes winning the Flutter test server's first
  request. The same full suite passes with that process temporarily suspended.
  Its exact process identity was checked and it was immediately resumed.
- iOS native release compilation and both Xcode archives pass.
- Both App Store exports pass strict/deep signature validation. The final apps
  use `iCloud.com.alkinum.serlink`, CloudKit `Production` and APNs `production`.
  iOS `get-task-allow` is false. macOS has App Sandbox and no debug entitlement.

  Production schemas with `SerlinkSyncObject`, `data` asset and queryable `path`.
  Snapshots are saved under `cloudkit/`. No schema deployment was needed.
- No reachable physical iPhone was available. Creation, edit, delete, conflict
  and remote notification flows between iOS and macOS in Production remain an
  explicit release gate. A schema/export check is not a runtime sync check.
