Serlink 1.0.0 — Mac App Store review notes

Serlink is an SSH terminal and SFTP client with no Serlink account or
subscription. SSH authentication is to a server chosen by the user.

Getting started:
1. Create a local vault with your chosen passphrase and save the recovery key.
   Biometric unlock is optional. Use disposable review credentials.
2. In Settings > Credentials, add your SSH identity. In Hosts, add a reachable
   host you control and select that identity. Connect and verify its SHA256
   host-key fingerprint before trusting it. No demo server is provided.
3. Run harmless commands (pwd, uptime, ls); search, reconnect or close the tab.
4. Open SFTP; transfer a disposable file using the native file picker. Inspect
   command snippets and Transfers for progress/history.
5. WebDAV and iCloud sync are optional. Core SSH/SFTP needs neither service.

App Store build behavior:
- Uses App Sandbox. Local shell, OS SSH-agent authentication, automatic
  ~/.ssh/config access and the standalone MCP stdio helper are disabled.
- The MCP HTTP server starts automatically, listens on 127.0.0.1 at a random
  port, and can be stopped in Settings. It requires a per-start bearer token;
  an agent opening an SSH session also requires separate in-app authorization.
  Serlink does not include an AI model or contact an AI provider by itself.
- Vault locking blocks new credential resolution; existing connections and
  transfers continue until closed. Diagnostics stay local unless exported;
  exports exclude terminal output and redact sensitive connection information.

Required incoming-network entitlement:
com.apple.security.network.server is required for actual TCP listeners in the
Mac App Store build, in addition to network.client for outgoing SSH/SFTP/sync:
- SSH local forwarding accepts local connections on 127.0.0.1 and forwards
  them through the SSH tunnel to a remote service.
- SSH dynamic forwarding accepts connections as a SOCKS proxy on the address
  and port selected by the user (127.0.0.1 is the default).
- MCP / Agent access accepts authenticated HTTP requests from local MCP
  clients at http://127.0.0.1:<port>/mcp. It never binds a LAN-facing address.
These incoming connections require network.server, not just network.client.

Verify SSH local forwarding:
1. Connect to your own SSH host as described above. In the connected terminal
   toolbar, open Manage port forwarding > Local.
2. Set Local port to 15422 (or another free port), Remote host to 127.0.0.1,
   and Remote port to that host's SSH port (usually 22). Click Start.
3. In macOS Terminal, run nc -v 127.0.0.1 15422. The remote SSH banner proves
   Serlink accepted the local connection and forwarded it. Press Control-C.
4. Stop the local forward in the same dialog; a new connection is refused.
   SOCKS Proxy in this dialog provides the separate dynamic listener.

Verify MCP without an SSH server or external AI service:
1. Open Settings > MCP / Agent access > Manage. Agent server shows its current
   loopback URL. If stopped, enable it. The switch also stops the server.
2. In macOS Terminal, set URL to the displayed URL and TOKEN to the Access
   token copied from this dialog. The token is for local testing only.
3. Run: curl -i -X POST "$URL" -H 'Content-Type: application/json' -d '{}'
   Without a bearer token, Serlink returns HTTP 403 Forbidden.
4. Run the following initialization request with the current token:
   curl -i -X POST "$URL" -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"App Review","version":"1.0"}}}'
   The JSON-RPC response identifies the Serlink MCP server. Initialization
   needs no SSH credentials, AI provider, or authorization to an SSH session.
5. Turn Agent server off and repeat the request: the listener is closed.
