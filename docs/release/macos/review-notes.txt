Serlink 1.0.0 — Mac App Store review instructions

No Serlink account or subscription is required. Two review paths are provided:

1. Populated offline demo (no setup required)
On Create/Unlock Vault, hold the large lock icon for about one second. If the
vault is open, hold the version label at the bottom of Settings. The same
preview is available to any user; its banner clearly identifies simulation.
Hosts, Sessions, Transfers, Snippets and Credentials contain sample content.
Open Review Sandbox; try help, pwd, ls, cat README.txt, mkdir and echo.
Terminal and SFTP share an editable in-memory filesystem. SFTP supports file
preview/edit, folders, rename, permissions and native-picker uploads/downloads.
Demo help explains the controls. Reset demo restores examples; Exit demo
returns to the original vault and discards demo data. Demo mode uses no real
vault, SSH, sync service, SSH agent or MCP connection.

2. Real SSH/SFTP review environment
Exit demo, create a local vault with any passphrase and save its recovery key.
In Settings > Credentials add a password credential using the private review
username/password. Add a Host using the private connection supplement, select
that credential and set SFTP starting folder to /workspace. Connect and compare
the SSH fingerprint with the supplement. Run pwd, ls -la, whoami, uname -a and
cat README.txt. Open SFTP; transfer disposable files, edit documents/notes.txt,
and inspect Transfers. The dedicated account has no sudo/admin access, an
isolated filesystem and restricted network access. Reviewers need no server
of their own. WebDAV/iCloud sync are optional; iCloud uses their own Apple ID.

Entitlements — purpose and where to verify:
- com.apple.security.app-sandbox: sandboxed Mac App Store operation.
- com.apple.security.files.user-selected.read-write: Open/Save/folder panels for
  SFTP/ZMODEM transfers, backup/import/export files and diagnostics. Broad
  com.apple.security.files.downloads.read-write is unnecessary and removed.
- com.apple.security.network.client: outgoing SSH/SFTP, optional WebDAV/iCloud
  sync and user-configured command-protection API. Test with the review host;
  Settings > Sync; Settings > MCP / Agent access > Command protection.
- com.apple.security.network.server: local SSH forwarding, dynamic SOCKS proxy,
  and authenticated loopback MCP HTTP. In a real connected terminal, open Manage
  port forwarding > Local: local port 18080, remote host 127.0.0.1, remote port
  8080. Visit http://127.0.0.1:18080 to see the sample tunnel page. Stop to close
  the listener. SOCKS can reach the same restricted destination.
  Settings > MCP / Agent access > Manage shows the URL, token and configuration;
  disabling Agent server closes it. MCP uses a random loopback port, a per-start
  bearer token and separate in-app grants for SSH control. No AI model is bundled.
- com.apple.developer.icloud-container-identifiers = iCloud.com.alkinum.serlink,
  com.apple.developer.icloud-services = CloudKit, and distribution-generated
  com.apple.developer.icloud-container-environment = Production: encrypted vault
  snapshots in the user's private CloudKit database, Settings > Sync > iCloud.
- com.apple.developer.aps-environment = production: silent CloudKit record-change
  notifications refresh encrypted sync data; no marketing/alert notifications.
- Signing-generated com.apple.application-identifier and
  com.apple.developer.team-identifier identify the signed app and developer.

Local shell, OS SSH-agent auth, automatic ~/.ssh/config access and the standalone
MCP stdio helper are disabled in the Mac App Store build.
