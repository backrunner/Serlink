Serlink 1.0.0 — Mac App Store review instructions

No Serlink account, subscription or in-app purchase is required.

1. Offline demo
Hold the lock icon on Create/Unlock Vault for one second, or hold the version
label in Settings. This preview is available to everyone and clearly marked
as simulated. Explore Hosts, Sessions, Transfers, Snippets and Credentials.
Open Review Sandbox; try help, pwd, ls, cat README.txt, mkdir and echo.
Terminal and SFTP share editable in-memory files. Test preview/edit, rename,
permissions and native-picker transfers. Exit demo discards its isolated data
and returns to the original vault. Real SSH, sync and MCP are outside demo.

2. Real SSH/SFTP
Exit demo, create a local vault and save its recovery key. Add a password
credential and Host using the private connection supplement; set SFTP folder
to /workspace. Verify the supplied fingerprint. Run pwd, ls -la, whoami,
uname -a and cat README.txt. In SFTP, transfer disposable files and edit
documents/notes.txt. The account has no sudo, an isolated filesystem and
restricted network. Reviewers need no SSH server of their own.

3. MCP and optional cloud command protection
Settings > MCP / Agent access > Manage displays a random loopback HTTP URL,
per-start bearer token and client configuration. Missing tokens return 403.
Discovery needs explicit consent before metadata is returned. Strict host
privacy limits hosts to names/IDs; startup commands and stored credentials
are excluded in either mode. New SSH/SFTP sessions need host authorization.
Borrowing an existing connection needs a separate connection-specific consent
covering the existing terminal buffer and file access. Revoke grants here.
Access notifications open the full in-app disclosure; short command approvals
can allow one execution. Denial, cancellation and timeout do not grant access.

Use serlink_list_connections / serlink_attach_session to borrow a connected
pane; closing agent access preserves it. Open a kind=sftp session, list files,
download a disposable file, and poll transfer status. MCP downloads go into
app-private storage. Use Export in Transfers for a native Save panel.
Stopping Agent server closes the HTTP listener.

Command protection is optional and off by default. In its Configure dialog,
review the TypeSafe data disclosure and privacy-policy link. Enabling requires
explicit consent and an API key; complete command text is sent to TypeSafe
for assessment and can contain sensitive data. Retention depends on TypeSafe's
terms; zero retention is not assumed. Keys are stored locally and transmitted
only for TypeSafe authentication, excluded from vault sync/backups. Use only
synthetic commands. The private supplement must include a limited review key
before the next submission; reviewers must not purchase their own access.
Without model protection, local command-risk rules still operate.

Entitlements:
- com.apple.security.app-sandbox: App Sandbox.
- com.apple.security.files.user-selected.read-write: native panels for manual
  transfers, exports/imports and diagnostics; MCP staging stays in-container.
- com.apple.security.network.client: SSH/SFTP, optional WebDAV/CloudKit and
  user-enabled TypeSafe requests.
- com.apple.security.network.server: local SSH forwards, SOCKS and MCP HTTP.
  On the review host, forward local port 18080 to remote 127.0.0.1:8080;
  open http://127.0.0.1:18080, then stop the forward.
- com.apple.developer.icloud-container-identifiers=iCloud.com.alkinum.serlink;
  com.apple.developer.icloud-services=CloudKit; exported container-environment
  Production: private encrypted vault sync, Settings > Sync > iCloud.
- com.apple.developer.aps-environment=production: silent CloudKit updates.
- com.apple.application-identifier and com.apple.developer.team-identifier:
  distribution signing identity.

Local shell, system SSH agents/hardware keys, automatic SSH-config access,
the MCP stdio helper and direct DMG installation are disabled in this edition.
